Промпт для разработки Android-клиента управления гаражными воротами

Роль и контекст: Ты — опытный Android-разработчик. Разработай Android-приложение на Java для удалённого управления гаражными воротами. Клиент взаимодействует с отдельно разрабатываемым сервером через REST API по HTTP. Требуется реализовать только Android-приложение.

1. Функциональные требования

1. Отображение состояния ворот. Показывай текущий статус в числовом и текстовом виде:
1 — закрыта;
2 — закрывается;
3 — открывается;
4 — открыта.

Отображай анимацию положения ворот в зависимости от полученного статуса.

2. Получение состояния. Используй GET /api/door/status. Обрабатывай поля status_code, status_text, lock_enabled.

3. Управление воротами. Добавь кнопки открытия и закрытия. Отправляй команды через POST /api/door/command с JSON-полями action и lock_enabled. Поддерживаемые команды: open, close, lock_on, lock_off.

4. Блокировка доступа. Добавь переключатель включения и отключения защиты от несанкционированного открытия. Синхронизируй его состояние с сервером, не отправляя повторную команду при обновлении переключателя из ответа сервера.

5. Журнал событий. Получай журнал через GET /api/door/logs. Отображай время события и описание, используя поля timestamp и event. Обновляй журнал при получении новых данных.

6. Периодический опрос. Регулярно запрашивай статус и журнал событий с сервера. Обеспечь обновление интерфейса по результатам запросов.

7. Уведомления безопасности. Предусмотри системное уведомление о попытке несанкционированного открытия, если в полученном журнале присутствует событие о недопустимой попытке.

8. Скрытая настройка адреса сервера.
Добавь в меню настроек пункт «Инструменты разработчика».
При трёх нажатиях на этот пункт открывай диалог настройки адреса сервера.
Используй одно текстовое поле для ввода полного URL, например http://192.168.1.50:8000/.
Сохраняй адрес локально через SharedPreferences, чтобы он сохранялся после перезапуска приложения.
При первом запуске используй адрес по умолчанию http://10.0.2.2:8000/.
Предусмотри кнопку сохранения и отмены изменения адреса.

9. Обработка ошибок. При ошибке сетевого подключения показывай уведомление об ошибке. При неуспешном HTTP-ответе на команду отображай сообщение с кодом ответа сервера.

2. Интерфейс

Создай простой интерфейс с текущим статусом ворот, анимированным изображением ворот, кнопками открытия и закрытия, переключателем блокировки, журналом событий и меню настроек.

В меню настроек должны быть пункты «Инструменты разработчика» и «О программе». Не добавляй отдельную страницу настройки IP-адреса: настройка подключения должна открываться через предусмотренный тройной клик.

3. Технические требования

Язык: Java.
Среда разработки: Android Studio.
Сборка: Gradle.
Для HTTP-запросов используй Retrofit и асинхронные callbacks.
Для хранения адреса сервера используй SharedPreferences.
Для уведомлений используй системные уведомления Android и канал уведомлений на поддерживаемых версиях ОС.
Не выполняй сетевые запросы в главном UI-потоке.
Не реализуй серверную часть и эмуляцию GPIO в клиенте.
Сохраняй простую архитектуру проекта без ненужных дополнительных зависимостей.

4. Формат результата

Предоставь структуру Android-проекта, полный код необходимых файлов с точными путями, настройки Gradle, AndroidManifest.xml и инструкцию по сборке и запуску в Android Studio.

Не ограничивайся отдельными фрагментами кода. Результат должен представлять собой собираемый Android-проект.

5. Примеры API-взаимодействия

Получение статуса ворот

GET /api/door/status

Пример ответа:

{"status_code": 1, "status_text": "Закрыта", "lock_enabled": false}

Команда открытия ворот

POST /api/door/command

Тело запроса:

{"action": "open", "lock_enabled": false}

Получение журнала событий

GET /api/door/logs

Пример ответа:

[{"timestamp": "2026-10-23T18:00:00+03:00", "event": "Дверь закрыта"}]

6. Критерии готовности

Приложение успешно собирается в Android Studio и запускается на Android-устройстве или эмуляторе.

Приложение отображает текущий статус ворот в числовом и текстовом формате.

Положение ворот визуально анимируется в соответствии с текущим статусом.

Пользователь может отправлять команды открытия и закрытия ворот через REST API.

Пользователь может включать и отключать блокировку ворот.

Приложение получает и отображает журнал событий с временными метками.

Статус ворот и журнал событий автоматически обновляются с сервера.

Адрес сервера можно изменить через скрытые настройки разработчика, и он сохраняется между запусками приложения.

При ошибках сети пользователь получает уведомление об ошибке.

При обнаружении в журнале события о недопустимой попытке открытия приложение показывает системное уведомление.
